## rc2.41 — Windows 通知与登录待办

登录首页显示待我审批、驳回/退回待修改、待提交草稿和审批消息。消息与业务审批同事务保存；每轮分别通知，撤回后不再提示过期的待审批事项。

安装包附带 Windows 通知助手，也可单独下载 `UG-DCMS-Notify-rc2.41.exe` 在局域网客户端运行，无需部署数据库或安装 Python。每台电脑运行助手，在网页登录首页点击“生成绑定信息”，复制到助手并连接。绑定码5分钟内一次有效，仅授权读取该登录账户的通知，不能办理审批；助手不保存密码或登录令牌、不增加登录会话。助手关闭窗口时收起到系统托盘，右键可测试通知或退出；每15秒检查消息，断网后重试。

通知涵盖待审批、审批通过、驳回和退回；点击弹窗打开申请，多条合并时打开首页。网页登录退出、会话到期、账户停用或首页“停用通知助手”后停止接收，重新登录后需要重新绑定。Windows 勿扰模式或通知设置可能隐藏弹窗，所有消息仍在系统首页显示。无需更改局域网 HTTP 部署或浏览器安全设置。

自动化验证覆盖真实 PostgreSQL 事务、HTTP 设备绑定与领取、账户隔离、撤回重提、并发去重、失效/撤销及登录首页浏览器操作；Windows 构建会执行编译后的助手 EXE、托盘和通知 API。CI 中通知 API 调用成功不代表用户电脑实际显示了弹窗。

## rc2.40 — 申请人审批操作

现有六类审批（设计族、文件版次、设计基线、外部件技术状态、项目准入、软件版本）统一支持：

- 申请人编辑、删除自己的待提交草稿；软件草稿可修改版本号/构建号和替换交付包。
- 最终批准前可以撤回修改或取消申请；审核中禁止直接修改或删除。
- 驳回、退回、撤回及取消后，可以编辑原对象，在同一申请编号下再次提交。
- 审批中心显示我的待提交草稿、我发起的申请、状态及每轮历史意见；已批准内容保持冻结。
- 所有业务状态写入使用对象行锁，避免批准与撤回同时成功；旧提交内容和处理意见留在不可变历史中。

自动化验证使用独立 PostgreSQL 数据库和真实浏览器，覆盖六类对象完整往返流程、权限隔离、软件包替换、历史保留和并发。Windows EXE 构建不等于用户电脑实际安装成功。

## rc2.39 — 独立 IMA 数据备份包

删除“IMA模拟数据”独立菜单。安装/升级不会自动写入数据。另下载 `UG-DCMS-IMA-Data-Backup-v1.zip`，安装后由管理员进入“系统 → 备份恢复 → 导入数据备份包”，选择 ZIP，输入“导入模拟数据”，点击“校验并导入数据”。无需解压或重启，完成后在正常业务模块查看。

这是增量逻辑备份：包内保存业务结构、构型、软件关联与模拟图纸模板，导入时分配目标系统件号，生成附件、冻结清单、审批记录及发布基线；不携带真实用户或密码。只接受配套、校验一致的 v1 数据包。原有“恢复系统”仍用于替换数据库和附件的全量备份，不能用它导入此数据包。目标是浏览器当前连接的 UG-DCMS 服务，无需提供数据库账号；当前开发环境没有连接用户生产系统。

- 固定批次 `SIM-IMA-V1`：19 个内部件（含 12 个组件）、9 个外部件、45 条 BOM 行、2 种构型、3 套软件、23 份设计附件、19 条设计基线及 82 个模拟审批申请。
- 一个顶层 P/N、一套主 BOM。A 使用基础计算板；B 使用增强计算板并增加扩展接口板。计算、电源模块各 2 套，共用导热板跨组件累计 4 件。
- 每个内部件都有发布的示意图及当前设计基线。所有组件冻结各自 BOM；顶层基线另锁定两份构型冻结清单、软件、外部技术状态、下级基线追溯清单和图纸手册。
- 全部名称、定义、附件和模拟审批明确标注模拟属性。基本图号仍按 T1/T2/T3 的现行正式发号规则分配并永久占号，不复用已有设计族或真实件号。
- 两个专用模拟身份分别编制、批准；通过现有审批服务及数据库约束，完成后立即停用，无默认登录密码，不代表真实人员签署。
- 模拟附件为 SVG 示意图、HTML 图纸手册和 JSON 冻结清单。软件 ZIP 仅含模拟说明及元数据，无可运行固件，不能用于制造、试验符合性或装机。
- 整批事务、非阻塞并发锁、不可变导入回执；重复执行返回原批次。固定模拟前缀若与现有记录冲突，停止导入并保留现有数据。异常回滚同时清理本次创建的附件。

验证：`ci/test-ima-demo.py` 在一次性 PostgreSQL 数据库运行，检查真实浏览器导入/导航/下载、权限、故障回滚、编号冲突、并发、原数据逐行保留、两种构型、软件关联、发布审批、固定基线和重复执行。Windows 构建与自动化测试不等同于用户电脑安装成功。
