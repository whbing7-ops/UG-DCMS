# UG-DCMS 界面补齐记录

本次以现有后端业务能力为边界，逐页检查入口、写操作和权限显示。源码归档仍保留，`ci/frontend` 和 `ci/backend` 为可审查的修订源码；Windows 构建通过 `patch-frontend-dom.ps1` 应用。

| 模块 | 本轮修订 |
|---|---|
| 账户管理 | 新建、编辑姓名/邮箱/角色、搜索、状态筛选、停用/启用、重置密码、解锁；显示中文角色和在线许可 |
| 登录与会话 | 首次改密后重新读取权限再跳转，退出时清理用户上下文；修改本人角色后立即刷新权限 |
| BOM 入口 | 主导航和首页的 BOM 管理入口；按父件号/中文名称检索并进入工作 BOM |
| BOM 明细 | 编辑项号、数量、单位、位号、适用性；添加/编辑与绑定规则在同一数据库事务内完成 |
| 适用性 | 通过表单创建规则与构型；支持且/或组合、文本/数字/布尔属性；保留高级临时属性输入 |
| 快照 | 列出当前父件号的历史 BOM/构型快照供选择、查看与比较；不存在/跨父件号比较明确拒绝 |
| 基线 | 新件号始终可进入基线列表并建立首条基线；补充取消草稿/在审基线 |
| 设计文件 | 关联文件入口及关联列表；取消版次、删除未发布附件；下载携带会话凭证，支持中文文件名 |
| 导入 | 下载模板携带会话凭证，补充取消导入批次 |
| 受控字典 | 启用/废止按钮及原因，保留只读角色限制；补齐制造商字典及外部件登记时制造商选择 |
| 号码 | 设计族内登记跳号；统计页显示基本图号占用 |
| 质量与审计 | 附件完整性问题/全量校验、发布活动、审计筛选与变更详情、系统自检入口 |
| 界面 | 深色分组导航、统一表单/按钮/表格/弹窗；表单标签关联、键盘操作、窄屏滚动；修复异步路由覆盖 |

## 验证方式

- `ci/test-ui-interactions.cjs`：真实浏览器点击 + 有状态 HTTP 测试夹具，检查交互、请求载荷、错误提示、下载和窄屏布局。它不是数据库联动验收。
- `ci/test-installed-actions.py`：Windows 安装包启动后，通过 Edge 实际登录、改密、创建/管理账户、维护/解析 BOM、上传/下载/删除中文附件、字典状态变更及基线/文件关联操作；同时核对持久化结果和原子回滚。
- `ci/full-functional-smoke.py`：保留独立工程师/审批员/构型管理员的业务 API 验证。
- `ci/windows-e2e-validation.ps1`：安装、服务、HTTP、并发、升级保留数据等安装环境检查；新增 FUNCTIONAL-03 界面操作检查，失败计入整个安装包验收。

具体通过与失败以对应提交的 GitHub Actions 日志和 `UI-ACTIONS-RESULTS.json` 为准。只打开页面、只通过接口或只用测试夹具点击，均不等于“所有功能已通过”。

安装不会增加固定演示账户。新数据库仍仅初始化 admin；普通业务账户由系统管理员新建并分配角色。
